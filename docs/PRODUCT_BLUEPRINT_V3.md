# 织脑（WeaveBrain）产品蓝图 V3

> 状态：开发冻结后的产品基线草案  
> 日期：2026-08-16  
> 覆盖范围：功能模块、信息架构、页面 DOM、卡片呈现、排序、交互预算、快捷录音、登录、导入、玩法和版本边界。  
> 说明：本文中的 DOM 指移动端页面信息架构与视图层级；数据领域模型见 `DOMAIN_AND_AI_SPEC_V3.md`。

## 1. 产品不可变目标

核心闭环固定为：

```text
快速捕捉 → 安全保存 →（用户开启时）AI 异步整理 → 用户回看/续写 → 旧想法再次产生价值
```

所有新功能必须至少满足一项：

1. 让用户更快捕捉；
2. 让原始想法更安全；
3. 让一条旧想法再次产生价值。

三项都不满足的功能，不进入主产品。

## 4. 首次使用和登录路径

登录不得挡在第一次记录之前。

```text
首次打开
→ 一页价值说明
→ 点击“先记录一条”
→ 触发时才请求麦克风权限
→ 进入本地游客模式
→ 第一次需要云端 AI/同步时提示登录
→ 登录后合并本地 Capture
```

### 4.1 账号阶段

| 阶段 | 认证方式 | 说明 |
|---|---|---|
| 本地游客 | 无账号 | 可记录、回看和导出，仅本机 |
| 私有 Alpha | 邀请码 + 邮箱验证码 | 降低短信接入和合规成本 |
| 国内公开 Beta | 手机号 OTP | 一种真实主身份方式 |
| iOS/海外 Beta | Sign in with Apple / Google | 按发布市场增加 |
| 后续 | 微信登录、设备扫码登录 | 有数据证明后再做 |

### 4.2 登录与同步 DOM

```text
AccountScreen
├─ 当前状态：仅本机 / 已登录并同步
├─ 登录或绑定账号
├─ 同步状态与最后同步时间
├─ 设备会话列表
├─ 本地记录合并状态
├─ 导出全部数据
└─ 退出登录 / 注销并删除账号
```

权限遵循“使用时再请求”：麦克风在首次录音时请求，通知在用户首次设提醒时请求，地点在用户主动开启“记住地点”时请求。

## 5. 全局捕捉 DOM

### 5.1 入口动作

点击全局捕捉按钮后，默认直接开始语音；长按或上滑出现：文字、单条导入、批量导入。

```text
CaptureOverlay
├─ 当前状态与计时
├─ 音量/录音反馈
├─ 实时转写（尽力而为，可关闭）
├─ 停止并保存
├─ 取消（需二次确认，防误触）
└─ 离线/存储空间/权限提示
```

录音停止后的主文案必须是“已安全保存”，不能是“正在请求 Agent”。用户无需选择项目、标签、模型或确认保存。

### 5.2 捕捉状态

```text
idle
→ recording
→ saved_local
→ pending_sync
→ synced
→ transcribing
→ organizing
→ ready
```

错误分支：

- `sync_failed`：本地副本仍在，可自动/手动重试；
- `transcription_failed`：原音频仍在，可重试或手动补文字；
- `organization_failed`：原音频和转写可用，可重试整理；
- `conflict`：保留两版，禁止静默覆盖；
- `storage_blocked`：录音前阻止并解释，不能录完才报错。

### 5.3 点击/动作预算

| 场景 | 最大主动动作 | 目标 |
|---|---:|---|
| App 已打开开始录音 | 1 次点击 | 点击即录 |
| 系统快捷入口开始录音 | 1 次点击/一次物理动作 | 不先打开首页 |
| 停止并保存 | 1 次点击或松开按键 | 无额外确认保存 |
| 文字速记 | 2 次 | 打开输入、完成 |
| 打开记忆详情 | 1 次 | 点击卡片 |
| 快速提醒“明天” | 2 次 | 提醒、选择预设 |
| 继续语音思考 | 2 次 | 继续、语音 |
| 切换排序 | 2 次 | 排序、目标排序 |

支持“按住说、松开保存”的入口时，可将一次记录压缩为一个连续手势。

## 6. 记忆卡类型

MVP 只设置一个主要类型，AI 建议、用户可修改：

| 类型 | 用途 | 默认下一步 |
|---|---|---|
| 闪念 | 创意、观察、突然想到的可能性 | 继续思考 |
| 问题 | 尚未解决的问题或疑问 | 回答/研究 |
| 行动 | 明确要做的事情 | 设置提醒 |
| 反思 | 日记、感受、复盘 | 稍后回看 |
| 资料 | 外部信息、引用、收藏 | 关联/归类 |

类型不是文件夹。一条记忆只能有一个主要类型，但可以有多个标签和多个关联。

## 7. 记忆流卡片 DOM

一张卡片只回答三个问题：这是什么、何时产生、下一步是什么。

```text
MemoryCard
├─ 顶部元信息
│  ├─ 主要类型
│  ├─ 处理状态：整理中/待补充/已整理/失败
│  └─ 置顶状态
├─ 一句话标题
├─ 原始内容摘要（最多两行）
├─ 情境
│  ├─ 真实产生时间
│  ├─ 来源：语音/文字/导入/分享
│  └─ 地点或活动（有真实数据才展示）
├─ 补充信息（有则显示）
│  ├─ 最多两个标签
│  ├─ 关联记忆数量
│  └─ 一个建议下一步
└─ 快捷操作
   ├─ 继续
   ├─ 提醒
   └─ 更多
```

### 7.1 字段展示规则

- 标题缺失：AI 未完成时显示原文前 20—30 字；完成后显示 AI 标题；
- 永远保留原始内容摘要，不能只显示 AI 改写；
- 标签最多展示 2 个，多余部分显示 `+N`；
- 下一步最多 1 个；
- 关联数量为 0 时不占空间；
- 地点默认不采集，不允许 AI 猜测；
- 不展示模型名、Token、温度、置信度和执行步骤；
- 点击次数不直接展示；在“常用记忆”中可以显示“回看 3 次”“续写 2 次”等有意义行为；
- 整理中和失败卡片仍可打开并查看原始记录。

### 7.2 卡片菜单

```text
MoreMenu
├─ 置顶/取消置顶
├─ 加入合集
├─ 标记待补充
├─ 归档
├─ 导出/分享
└─ 删除
```

删除默认进入 30 天回收站；永久删除需要二次确认，并级联删除音频、转写、向量和派生内容。

```text
MemoryDetail

│  ├─ 返回
│  ├─ 置顶
│  ├─ 分享
│  └─ 更多
├─ 核心区

│  ├─ 主要类型与处理状态

│  └─ 标签
├─ 原始记忆
│  ├─ 原始文字
│  ├─ 原始音频播放器/波形
│  └─ 查看并修正转写
├─ AI 整理
│  ├─ 一句话核心
│  ├─ 要点（最多 3 条）
│  ├─ 待确认问题（最多 1 条）
│  └─ 建议下一步（最多 1 条）
├─ 继续思考
│  ├─ 文字续写
│  ├─ 语音续写
│  ├─ 追加为当前记忆的新片段
│  └─ 生成独立记忆并建立关联
├─ 关联记忆
│  ├─ 1—3 张关联卡
│  └─ 每条的“为什么相关”
├─ 提醒与回响
│  ├─ 当前提醒
│  ├─ 新建/修改提醒
│  └─ 有用/无关/稍后反馈
└─ 历史与元数据（默认折叠）
   ├─ 创建、同步、转写、整理时间
   ├─ 来源和导入文件
   ├─ 用户编辑版本
   └─ AI 派生版本
```

必须保持三层内容分离：

1. 原始记录：不可被 AI 覆盖；
2. AI 派生：可删除、重做和回退；
3. 用户编辑：优先级最高，重新生成时不能覆盖。

## 9. 排序、时间线和点击统计

### 9.1 记忆流排序

MVP：

1. 最近记录：默认，按 `captured_at DESC, id DESC`；
2. 最早记录：按 `captured_at ASC, id ASC`；
3. 最近更新：按续写、编辑、提醒等 `updated_at DESC`；
4. 常用记忆：按有效行为聚合，不使用原始点击数；
5. 置顶优先：在所有排序中作为独立层。

Beta：

- 最常续写；
- 待处理优先；
- 关联最多；
- 搜索结果相关度；
- 回响推荐分。

主记忆流不默认使用不可解释的 AI 推荐排序。智能推荐只放在“回响”中，并说明“为什么再次出现”。

### 9.2 点击和互动统计

记录以下有效事件：

- 打开详情；
- 播放原音频；
- 续写；
- 编辑；
- 设置/完成提醒；
- 标记有用/无关；
- 分享/导出；
- 置顶/归档。

同一卡片在同一会话或 30 分钟内重复打开，只计一次有效回看，避免点击数被刷新放大。

“常用记忆”的 MVP 排序优先级：置顶 > 续写 > 标记有用 > 提醒/导出 > 有效回看 > 最近使用。

### 9.3 时间视图

- 默认按真实 `captured_at` 分日分组；
- `created_at` 仅代表服务器接收时间，不能替代产生时间；
- 导入记录缺少原始时间时进入“时间未知”，不伪造成导入当天产生；
- `updated_at` 用于“最近更新”视图；
- 活动日志与记忆时间线是两个概念，普通用户只看记忆时间线。

### 9.4 筛选

MVP：时间范围、来源、主要类型、处理状态、收藏/置顶。

Beta：标签、合集/项目、有无提醒、有无音频、地点、有无关联。

顶部最多展示 2—3 个常用筛选 Chip，其他筛选进入完整面板。

## 10. 搜索

```text
SearchScreen
├─ 输入框与最近搜索
├─ 关键词/语义混合结果
├─ 结果中的匹配片段
├─ 时间、类型、来源筛选
└─ 排序：相关度/最近/最常回看
```

MVP 搜索先保证全文准确；语义检索加入后使用混合搜索。AI 回答必须附来源记忆，不允许只给无法追溯的结论。

## 11. 回响

回响不是随机推荐，而是“有理由地重新出现”。

### 11.1 MVP

- 每日或隔日最多 1—3 条；
- 来源包括：用户设定提醒、待补充、近期重复主题、较久未看的高价值记忆；
- 每条说明原因，例如“你本周第三次提到这个主题”；
- 操作：继续、完成、稍后、无关；
- 支持关闭、频率和静默时段。

### 11.2 Later 玩法

- 每周主题聚合；
- 思想分支与演化；
- 时间/地点镜头；
- “当年今日”；
- 跑步结束后的思维总结；
- 问题队列；
- 主题星图；
- 将多条记忆合成为文章/方案；
- 外部工具执行。

## 12. 快速语音入口矩阵

软件无需永久打开，也不设计永久监听麦克风。“存在感”由系统入口提供，录音必须由用户显式触发。

| 入口 | Android | iOS | 阶段 | 体验 |
|---|---|---|---|---|
| 应用内全局录音按钮 | 支持 | 支持 | MVP | 一次点击开始 |
| 长按应用图标/独立快捷项 | App Shortcut | App Shortcut | MVP | 直达极简录音页 |
| 桌面小组件 | Widget | Widget | MVP/Beta | 一个大录音按钮 |
| 快捷设置/控制中心 | Quick Settings Tile | Control Center Control | Beta | 不打开主页即可触发 |
| 锁屏入口 | Widget/通知，受厂商影响 | Lock Screen Control/Widget | Beta | 锁屏快速启动 |
| 常驻入口 | 克制的可选通知 | 不采用传统常驻通知 | Beta | 只作为按钮，不后台监听 |
| 语音助手 | 设备支持差异较大 | Siri/App Shortcuts | Beta | “用织脑记录” |
| 物理 Action Button | 不适用 | 支持机型 | Beta | 绑定 App Shortcut |
| 桌面全局快捷键 | Windows/macOS 客户端 | Windows/macOS 客户端 | Beta | 小窗立即录音 |
| 手表 | Wear OS | watchOS | Later | 跑步场景强化 |
| 耳机按键 | 可靠性不足 | 可靠性不足 | 研究 | 暂不承诺 |
| 永久监听唤醒词 | 不做 | 不做 | 不进入规划 | 隐私、功耗和平台风险过高 |

实现上需要 Flutter 与 Android/iOS 原生能力协作，不能仅依赖通用录音插件。

## 14. AI 设置 DOM

普通用户只看到可理解的模式：

```text
IntelligenceSettings
├─ 整理模式
│  ├─ 仅记录：原始内容 + 转写
│  ├─ 智能整理：标题、核心、标签、关联（默认）
│  └─ 深度启发：额外问题与下一步，按需触发
├─ 云端转写 开/关
├─ AI 摘要 开/关
├─ 自动标签 开/关
├─ 关联记忆 开/关
├─ 主动回响 开/关
├─ 记录地点 开/关
├─ 音频保留周期
└─ 语言与专有词
```

模型名称、temperature、Base URL、Prompt 版本、Token 和路由只进入隐藏的运营/开发者配置。
### 14.1 “AI 记忆整理”总开关（正式产品规则）

入口固定为：“我的 → AI 与自动化 → AI 记忆整理”。

AI 记忆整理 [开/关]：开启后，新记录会在后台生成标题、核心、标签、关联和回响；关闭后，只保存为普通备忘录，不再触发这些 AI 任务。

行为必须符合下表：

| 场景 | 行为 |
|---|---|
| 初次安装 | 默认关闭；在用户第一次主动体验智能能力时说明数据用途并明确开启 |
| 打开后新建记录 | 本地先保存，随后按设置异步整理 |
| 关闭后新建记录 | 只保存原文/音频；语音转写由独立开关决定；标题用原文前 20—30 字回退 |
| 关闭已有开关 | 只影响之后的新记录；已生成的 AI 内容保留并标记来源 |
| 正在执行的任务 | 已运行任务允许完成；排队但未运行的整理任务取消，界面说明数量 |
| 再次打开 | 默认只处理之后的新记录；提供一次性“补整理未处理记忆”，不得静默回溯 |
| 子开关 | 总开关关闭时摘要、标签、关联、回响不可执行，但保存原值，重新开启后恢复 |
| 单条例外 | 关闭总开关时，详情页仍可由用户主动点击“仅整理这一条”，并再次确认 |

“云端转写”与“AI 记忆整理”必须分开。用户可以选择“语音转成文字，但不做摘要、标签、关联和回响”。关闭总开关时，后台整理模型调用数必须为零。

### 14.2 AI 补全：独立于自动整理的核心能力

AI 补全不是替用户编造记忆，而是“检测缺失 → 给出建议 → 用户预览 → 选择应用”。入口覆盖：

- 新记录保存后的轻提示：“还可补全 3 项”；
- 记忆详情的“AI 补全”；
- 单条导入预览；
- 批量导入字段映射后的“补全缺失项”；
- Beta 的旧记忆批量补全。

可补全边界：

| 类型 | 字段 | 规则 |
|---|---|---|
| 可自动生成但仍可撤销 | 标题、主要类型、核心摘要、要点、标签、下一步、开放问题 | 只基于原文/转写；显示“AI 建议” |
| 仅建议、必须确认 | 文本中可识别的估算日期、来源、合集、人物/实体 | 展示证据片段、置信提示和“时间为估算” |
| 可继承 | 时区、语言、默认合集 | 标记“继承自账户/导入批次” |
| 禁止猜测 | 地点/坐标、身份、未在原文出现的事实、缺失正文 | 保持未知并提示用户补充 |

补全预览 DOM：

- 缺失项数量 + 预计处理范围；
- 字段建议列表：字段名、原值、AI 建议值、来源证据、接受/忽略；
- 全部采用“安全字段”；
- 应用所选；
- 取消。

必须支持逐字段采用、全部采用安全字段、撤销和版本历史。AI 默认只填空字段，不覆盖用户值或导入原值；如需改写，必须单独显示前后对比并确认。批量导入开始补全前展示预计条数、耗时/额度和示例结果。

### 14.3 首发平台冻结：手机端 + Web 端

| 端 | 首发定位 | MVP 责任 |
|---|---|---|
| 手机端（Flutter，Android/iOS） | 捕捉主端 | 录音/文字、本地可靠保存、系统快捷入口、记忆流、轻量详情 |
| Web 端 | 回顾与生产力端 | 搜索、完整详情、批量导入、设置、数据管理、工作流方案设计入口 |

Web 只有在页面打开且用户授权时才能录音，不承诺浏览器关闭后的系统级唤起。移动端的快捷入口需要 Flutter 与原生能力协作。手表、耳机、车机和其他硬件只保留统一 Capture 接口与 source 枚举，不进入 MVP/Beta 实现承诺。

### 14.4 工作流方案设计器：保留页面与契约，暂不执行

工作流的核心定位是让用户未来设计自己的记忆处理方案，不是向用户暴露底层 Agent 日志。

Web 页面结构：

- /workflows：我的方案、空状态、示例方案、新建入口（MVP 显示“规划中”）；
- /workflows/:id/designer：触发、条件、步骤、输出、校验与发布；
- 触发：记录后、导入后、定时、手动；
- 条件：类型、标签、来源、合集；
- 步骤：整理、补全、关联、提醒、导出；
- 输出：更新卡片、生成回响、外部动作；
- 校验与发布在当前阶段均不可执行。

MVP 只做以下预留：

1. Web 和“我的”中保留可见入口，并明确标记“规划中”，不制作可误认为可用的假编辑器；
2. 路由预留 /workflows、/workflows/:id/designer；
3. 领域接口预留 WorkflowDefinition/Version/Node/Edge；
4. GET /api/v3/capabilities 返回 workflow_designer=false、workflow_execution=false；
5. OpenAPI 命名空间预留，任何写入或运行请求统一返回 FEATURE_NOT_ENABLED；
6. 外部副作用节点未来必须逐项授权、可审计、可撤销，不能因为开启 AI 整理而自动获得权限。

工作流正式执行进入 Later；Beta 最多开放本地草稿、模板和静态校验，不连接真实 Agent 或外部工具。

### 14.5 本轮产品决策记录

- AI 记忆整理必须有用户可见的总开关，关闭后产品退化为可靠的普通备忘录；
- AI 补全列为 MVP 核心功能，尤其服务单条/批量导入和缺失字段补充；
- 首发产品只承诺手机端与 Web 端，其他硬件只保留扩展契约；
- 工作流设计页、路由和接口需要预留，但本阶段不开发编辑、发布和执行。

## 15. 页面状态规范

| 状态 | 呈现 | 主要动作 |
|---|---|---|
| 首次空状态 | “随手说一句，之后由 AI 整理” | 开始录音 |
| 搜索无结果 | 显示关键词与筛选条件 | 清除筛选 |
| 加载 | 首屏卡片骨架 | 无 |
| 整理中 | 原始内容可打开 | 稍后查看 |
| 转写失败 | 原音频可播放 | 重试/补文字 |
| AI 失败 | 原文可使用 | 重试整理 |
| 离线 | “已离线，将稍后同步” | 查看待同步 |
| 同步冲突 | 并列保留版本 | 选择/合并 |
| 麦克风占用 | 解释被其他 App 使用 | 改用文字 |
| 权限拒绝 | 不重复弹系统框 | 打开设置/文字记录 |
| 空间不足 | 录音前阻止 | 清理空间 |
| 导入部分失败 | 成功项正常入库 | 查看/下载错误报告 |

## 16. 冻结边界

### MVP

- 本地优先语音和文字记录；
- 记忆流、详情、原音频、转写和轻量 AI 整理；
- 搜索、基础排序筛选、继续、单次提醒；
- 时间、来源和可选地点；
- 单条导入、文本/CSV/JSONL 基础批量导入；
- 游客模式和一种真实登录方式；
- “AI 记忆整理”总开关与无 AI 的纯备忘录路径；
- AI 补全预览、逐字段采用、导入缺失项补全和撤销；
- 手机端（Flutter Android/iOS）捕捉体验与 Web 端回顾、导入、设置；
- 至少一种移动系统快捷入口；
- 工作流页面、路由、领域对象和 capabilities 接口预留，不执行；
- 一种回响；
- 数据导出、回收站和删除。

### Beta

- Android/iOS 完整系统快捷入口；
- 跨设备同步和冲突处理；
- 语义搜索、关联理由、回响反馈；
- 多格式导入、字段映射、分享接收；
- 项目/合集、推送与静默时段；
- 多种正式登录方式；
- 工作流本地草稿、模板和静态校验（是否进入 Beta 由数据决定）。

### Later

- 手表；
- 关系图谱和主题演化；
- 专用外部导入连接器；
- BYOK、自选模型和完全端侧模型；
- MCP、Notion、邮箱和自动外部行动；
- 多人协作、会议、可执行工作流、复杂 Agent 与外部动作。

## 17. 开发前必须拍板

1. Android 与 iOS 都使用 Flutter，但首批系统快捷入口先重点打磨哪一端；
2. Web Alpha 是否首批即包含完整批量导入，还是先只做回顾、搜索和设置；
3. 私有 Alpha 使用邮箱验证码，还是直接投入手机号 OTP；
4. 云端原始音频默认保留期：建议 30 天，可选永久、仅本机或转写后删除；
5. MVP 是否把“回响”做成独立一级导航，还是先放在记忆首页；
6. 地点只保存地点名称，还是允许保存精确坐标；建议默认仅粗粒度地点且显式授权。
