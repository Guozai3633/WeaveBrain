# 织脑（WeaveBrain）V2 路线图

> 日期：2026-08-16  
> 原则：先修可靠捕捉，再做 AI 价值；每个阶段必须由用户可验证的结果结束。
> 具体执行轮次、验收关卡与当前状态：DEVELOPMENT_ROUNDS_PLAN_V1.md  

## 0. 当前项目状态

当前应标记为 **Pre-MVP 技术原型**。

虽然仓库已经包含语音、Agent、Temporal、pgvector、MCP、时间线等模块，但核心用户闭环没有稳定接通，移动端也存在编译、权限、真机连接、离线和安全问题。V2 不按已有 Sprint 数量衡量进度，改为按以下四项衡量：

1. 能否无摩擦捕捉；
2. 是否绝不丢失；
3. AI 整理是否有用；
4. 旧想法能否被恰当地重新带回。

## 0.1 已冻结产品约束

- 首发端固定为手机端（Flutter Android/iOS）与 Web 端；手机负责快速捕捉，Web 负责回顾、导入、设置和方案设计；
- “我的”必须提供 AI 记忆整理总开关；关闭后只做普通备忘录，语音转写使用独立开关；
- AI 补全进入 MVP，采用“检测缺失—预览建议—逐字段应用—可撤销”，不猜测地点或原文不存在的事实；
- 工作流方案设计器只预留页面、路由、领域接口和能力探测，MVP 不开发发布与执行；
- 手表、耳机、车机等只保留 Capture source 与接口扩展，不进入当前实现。

## Phase 0：止损与基线（1 周）

### 目标

冻结扩展功能，建立一个可编译、可运行、可复现的基线。

### 工作项

- 暂停 MCP、时间线、复杂项目管理和新 Agent 工具开发；
- 整理当前大量未提交改动，按功能拆分并决定保留或撤销；
- 修复 Flutter 编译错误、Android/iOS 录音权限和真机 API 配置；
- 建立一条干净环境启动路径：配置检查、自动迁移、健康检查；
- 修复认证冒充、跨用户读写、开发 JWT secret 和明文传输问题；
- 定义产品事件：capture_started、capture_saved_local、capture_synced、enrichment_completed、memory_revisited；
- 用 10 名目标用户做问题访谈，并实际试用 2—3 个竞品；
- 明确首发平台与原始音频保留策略。

### 验收标准

- `go test ./...`、`go vet ./...`、`flutter analyze`、`flutter test` 全部通过；
- 新环境可以一条命令启动并完成数据库迁移；
- P0 安全问题有测试覆盖；
- PRD V2、核心流程和事件定义评审通过；
- 没有继续新增非核心功能。

## Phase 1：可靠捕捉内核（2—3 周）

### 目标

即使断网、后端或 AI 不可用，用户的原始想法也不会丢。

### 客户端

- 引入本地数据库和音频文件管理；
- 用客户端生成的 UUID 作为幂等 capture_id；
- 一次操作开始/停止录音，停止后立即本地落盘；
- 状态机：recording → saved_local → pending_sync → synced → processing → ready / retryable_error；
- 断网队列、应用重启恢复、失败重试；
- 时间、时区、入口来源和可选地点采集；
- 提供文本快速记录兜底；
- 清晰的声音/触觉/视觉反馈和取消、撤销能力。

### 后端

- 新增幂等 `POST /captures`，立即保存原始记录并返回；
- 原始捕捉与 AI 派生内容逻辑分离；
- 项目归属改为可选，默认进入 Inbox；
- 增加 captured_at、timezone、source、audio_ref、processing_status、context、version 等字段；
- 音频上传支持重试，服务端不以 LLM 成功作为创建成功条件；
- 使用数据库 Outbox 或轻量任务队列驱动后续处理；
- 暂时绕过单条捕捉热路径中的 Temporal 和 ReAct。

### 验收标准

- 飞行模式下连续录制 20 条，重启 App 后全部仍存在；
- 恢复网络后全部成功同步且无重复；
- 强制关闭后端、STT、LLM，捕捉仍能成功；
- 停止后 P95 1 秒内显示“已安全保存”；
- 重复提交同一 capture_id 不产生重复记录；
- 录音生命周期、权限拒绝、断线、尾句和重试均有自动化测试。

## Phase 2：真实转写与轻量整理卡（2—3 周）

### 目标

用户稍后打开 App 时，能看到准确、简短、可继续的记忆卡，而不是一份冗长的 AI 报告。

### 工作项

- 接入一个真实稳定的中文 STT Provider，并保留失败重试；
- 音频和原始转写可回放、可校正；
- 使用模型原生结构化输出或 JSON Schema；
- 实现 UserAISettings、设置版本与 Capture 策略快照；
- 在“我的”提供 AI 记忆整理总开关、AI 补全开关和独立转写开关；
- AI 关闭时只生成 fallback 卡片，不创建 organize/embed/relate/recap 任务；
- AI 补全先生成 FieldProposal，支持证据、逐字段采用、版本和撤销；
- 单次整理输出限定为：title、essence、open_question、next_step、tags、confidence；
- 删除强制 feasibility 评分；
- Agent 只做 enrichment，不允许自主创建记录或执行外部工具；
- 卡片支持“有用/无关”“修正”“稍后提醒”；
- 详情页按 ID 加载，支持通知和深链恢复。

### 验收标准

- 真实中文口语样本集转写达到可接受准确率；
- 95% 以上任务最终进入 ready 或明确的 retryable_error；
- 原始记录始终可见，AI 输出失败不会覆盖它；
- 20 名内测用户中，超过 60% 认为卡片准确表达了原意；
- 单张卡首屏只出现一个主要下一步。
- AI 总开关关闭时连续新增 50 条，后台整理模型调用数为 0；
- 关闭整理但开启转写时，音频仍可转成文字且不会继续生成派生内容；
- 补全 preview 不改数据，apply 不覆盖用户值或导入原值；
- 再次开启 AI 不会静默回溯处理历史记录。

## Phase 3：长期记忆与主动复现（2—4 周）

### 目标

证明织脑的价值不止是“录下来”，而是能让旧想法重新产生价值。

### 工作项

- Embedding 使用持久任务和重试，不使用裸 goroutine；
- 关联 1—3 条历史记忆，并提供“为什么相关”；
- 先上线一种复现：每日/隔日回访或每周主题回顾；
- 记录有用、无关、稍后等反馈，调整个性化；
- 可选的时间、地点、活动上下文检索；
- 提供“询问我的记忆”，回答必须附来源卡片；
- 通知支持频率、静默时段和一键关闭。

### 验收标准

- 7 日有效复用率达到 30% 的内测目标；
- 关联结果“有用”反馈高于“无关”；
- 所有回答可追溯到原始记录；
- 复现提醒关闭率和打扰反馈处于可接受范围；
- 删除一条记录后，向量、派生内容和音频均可完整删除。

## Phase 4：低摩擦入口与手机/Web 双端（2—4 周）

### 目标

让手机端在跑步、散步和通勤时真正做到少看屏幕，同时让 Web 端承担高效回顾、导入和配置。

### 工作项

- 根据首发平台实现一种系统级入口：
  - Android：Quick Settings Tile、桌面小组件或通知快捷入口；
  - iOS：Shortcut、锁屏小组件、Action Button 或 Siri；
- 通过声音/振动确认“开始录音”和“已保存”；
- 建立 Web 回顾端：记忆流、搜索、完整详情、批量导入、AI 设置和数据管理；
- Web 页面打开且授权时可录音，但不承诺浏览器关闭后的系统级唤起；
- 保留 /workflows 与设计器路由、capabilities 和 WorkflowDefinition/Node/Edge 契约，界面标记“规划中”；
- 手表、耳机、车机和桌面原生端只保留扩展接口，不进入本阶段实现。

### 验收标准

- 从系统入口到开始录音 P50 < 1.5 秒；
- 捕捉全程最多一次主动操作；
- 不解锁或极少看屏幕即可完成一次记录；
- 快捷入口带来的周捕捉量显著高于仅打开 App 的用户。
- 手机与 Web 的原文、版本和处理状态最终一致；
- 工作流 capabilities 返回不可用，误调用不会创建任务或外部副作用；
- Web 能完成批量导入预览、AI 补全预览和设置修改。

## Phase 5：Beta 上市与商业验证（持续）

### 上市前必须完成

- 真实认证、HTTPS/WSS、用户隔离、密钥管理；
- 隐私政策、服务协议、麦克风/定位说明；
- 数据导出、账号删除、音频保留策略；
- 崩溃监控、任务失败监控、成本监控和基础客服反馈渠道；
- 商店名称、图标、截图、版本号和 Release 签名；
- 30 名以上种子用户完成 4 周内测。

### 商业化假设

- 免费层：可靠捕捉、有限 AI 整理、有限历史；
- 订阅层：更多转写、无限历史记忆、主动复现、跨端和高级隐私选项；
- MCP、Notion、邮件、团队协作进入付费 Beta，而不是 MVP。

## 技术取舍表

| 模块 | 决策 | 原因 |
|---|---|---|
| Flutter | 保留 | 移动双端共享价值高，现有骨架可复用 |
| Go + Gin + PostgreSQL | 保留 | 足以支撑 MVP，当前基础资产较完整 |
| pgvector | 保留但后置 | 长期记忆有价值，不应阻塞捕捉 |
| Provider 抽象 | 保留 | 便于切换 STT/LLM 和隐私方案 |
| ReAct Supervisor | 移出热路径 | 成本、延迟和行为不确定，不适合确定性保存 |
| Temporal | 暂停用于单条捕捉 | 当前复杂度高于收益；可用于未来长任务 |
| MCP | 冻结到 Beta | 市场差异化弱，且增加安全与配置成本 |
| Redis 限流 | 可保留 | 不应成为当前开发重点 |
| 时间线执行日志 | 从 MVP UI 移除 | 不等于用户需要的记忆回顾 |
| Web 端 | MVP 建设 | 作为回顾、导入、设置和未来工作流设计主端 |
| 工作流设计器 | 仅预留页面与契约 | 先冻结扩展点，不提前建设执行引擎 |

## 下一批开发任务顺序

1. 修复 Flutter 编译、权限、真机配置和安全传输；
2. 修复认证与跨用户数据隔离；
3. 设计 Capture、UserAISettings、CompletionProposal 与幂等 API；
4. 实现客户端本地音频/草稿存储与离线队列；
5. 改造后端为“先保存、按设置异步 enrichment”；
6. 实现 AI 总开关、独立转写开关和任务取消/快照规则；
7. 接入真实 STT、轻量卡片与 AI 补全预览/应用；
8. 建设 Web 回顾、搜索、批量导入和设置端；
9. 预留工作流页面、路由、Schema 和 capabilities，不接执行器；
10. 建立核心路径自动化测试和干净环境启动；
11. 最后恢复长期记忆、主动复现与更多系统快捷入口。
