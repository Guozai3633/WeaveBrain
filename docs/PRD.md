# 织脑 (WeaveBrain) - 产品需求文档 (PRD)

## 1. 产品概述

### 1.1 产品定位
**织脑 (WeaveBrain)**：一个以语音为入口、Agent为引擎的个人思维外脑。

核心价值不是"记录"，而是从想法到行动的全链路自动化：
- 用户随时语音说出一个想法
- Agent 理解意图、归类、关联历史想法
- 需要时调用 MCP 工具执行（创建 Notion 页面、发日历提醒、发邮件...）
- 定时主动回来问用户"这个想法你要继续推进吗？"

### 1.2 目标用户
国内专业人士和学生群体，他们经常在工作、散步、通勤时有即时灵感，但缺乏合适的工具来捕获、整理和跟进这些想法。

### 1.3 差异化优势
- **主动而非被动**：传统备忘录只记录不行动。织脑的 Agent 会主动关联历史想法、分析意图、定时提醒跟进
- **MCP 执行能力**：不仅记录想法，还能直接调用外部工具执行（Notion、邮箱、日历等）
- **项目化隔离**：每个想法归属于特定项目，支持多项目知识管理
- **用户画像长期记忆**：持续学习用户偏好，提供个性化建议

### 1.4 竞品分析
- 闪念胶囊：被动记录，无 Agent 处理能力
- 微信听书：侧重听书场景，非即时灵感
- Notion AI：无语音入口，需手动输入
- 腾讯会议 AI：仅针对会议场景

## 2. 用户故事

### 2.1 核心用户故事
**作为** 一个经常在工作时产生灵感的人
**我希望** 通过语音快速记录想法并让 Agent 自动整理
**以便** 我的灵感不会被遗忘，且能被有效利用

### 2.2 场景一：散步时的灵光一现
1. 用户在散步时想到一个项目构思
2. 打开 App，点击大大的麦克风按钮
3. 语音说出想法，文字实时流式显示
4. 确认后，Agent 分析：归类标签、关联历史想法、建议下一步
5. 结果存入"想法簿"，按项目分块展示

### 2.3 场景二：定时跟进
1. 三天后，Agent 定时推送通知
2. "你三天前提到的 [想法内容]，要继续推进吗？"
3. 用户点击"继续"，Agent 自动调用 MCP 工具（如在 Notion 中创建任务）

## 3. 功能规格

### 3.1 快捷登录

#### 3.1.1 微信登录
- 通过微信 OAuth2.0 授权登录
- 登录后默认绑定该微信账号关联的手机号
- 用户可选择是否关联其他手机号（不影响微信绑定）
- 微信实名信息作为额外身份凭证存储

#### 3.1.2 QQ登录
- 通过 QQ OAuth2.0 授权登录
- 逻辑同微信登录
- QQ 绑定手机号默认关联，支持绑定其他手机号

#### 3.1.3 手机号登录
- 手机号 + 短信验证码登录
- 最直接方式，不依赖第三方账号

#### 3.1.4 身份模型设计
- 核心标识：系统内部 `UserID`（UUID）
- 身份凭证表（Identities）：一个 UserID 可绑定多个 Identity（WeChat/OpenID, QQ/OpenID, Phone 号码）
- 解耦设计：更换手机号不影响项目数据，仅更新 Identity 表记录

### 3.2 项目隔离

#### 3.2.1 默认项目
- 用户注册时自动创建"默认项目"
- 用户未指定目标项目时，所有想法默认存入默认项目

#### 3.2.2 自定义项目
- 用户可创建、重命名、删除自定义项目
- 每个项目独立管理自己的：想法集合、标签体系、RAG 知识库、MCP 工具权限
- 项目间数据完全隔离

#### 3.2.3 项目切换
- 语音输入时，用户可指定"记到XX项目"
- Agent 环境上下文智能体自动识别目标项目

### 3.3 语音输入

#### 3.3.1 入口设计（MVP）
- **首页麦克风按钮**：App 打开即见，全宽度居中按钮，最显眼位置
- 桌面快捷方式/后台挂起：Phase 2
- 桌面端快捷键录音：Phase 2

#### 3.3.2 录音流程
1. 用户点击麦克风按钮 → 开始录音
2. 音频流通过 WebSocket 实时发送到后端
3. 后端代理到 STT 提供商（阿里云/讯飞）的 WebSocket 接口
4. 文字流式返回，实时显示在 App 上
5. 录音结束 → AI 审核文本清晰度，建议修改（可选）
6. 用户确认/修改 → 发送给 Agent 集群处理

#### 3.3.3 STT 提供商
- **方案A（推荐）：阿里云智能语音交互**
  - 优势：成本划算，免费额度大，普通话识别率高，WebSocket 实时识别
  - 适用：普通话场景、批量处理
- **方案B：科大讯飞**
  - 优势：普通话识别率 98%+，复杂环境抗噪强，支持方言
  - 适用：噪音环境、多方言场景
  - 成本：高于阿里云
- 用户可在设置中切换 STT 提供商

#### 3.3.4 AI 内容审核
- STT 完成后，LLM 自动审核文本：检查是否有内容不清晰、错别字
- 提供修改建议（仅建议，用户决定是否修改）
- 审核通过后发送给 Agent 集群

### 3.4 Agent 协同（核心功能）

#### 3.4.1 架构概述
- 主智能体（Supervisor Agent）接收用户想法，拆分成子任务，分发给多个 Worker Agent 并行处理
- 最终汇总所有 Worker 结果，生成结构化响应
- 使用 Eino 框架的 Supervisor Pattern 实现

#### 3.4.2 主智能体 (Supervisor Agent)
- **职责**：接收用户想法 → 理解意图 → 分解任务 → 分发给 Worker → 综合结果
- **实现**：Eino Agent，使用 ReAct 循环 + 工具调用
- **行为**：
  - 调用环境上下文智能体确定目标项目
  - 调用用户画像智能体获取用户偏好
  - 根据想法类型决定是否需要调用 MCP 工具
  - 综合所有结果，生成结构化响应

#### 3.4.3 环境上下文智能体 (Environment Context Agent)
- **职责**：确定想法所属项目，检索相关历史想法
- **实现**：RAG 语义检索 + 项目元数据查询
- **行为**：
  - 根据用户指令或 Agent 分析确定目标项目
  - 在目标项目中对历史想法进行向量相似度检索
  - 返回相关历史想法摘要（经 LLM 压缩）给主智能体

#### 3.4.4 用户画像智能体 (User Profile Agent)
- **职责**：维护长期用户画像，提供个性化上下文
- **实现**：PostgreSQL JSONB 字段存储，定期更新
- **行为**：
  - 从用户所有想法中提取模式、偏好、常见主题
  - 提供个性化建议给主智能体
  - 无感更新，不干扰用户正常使用

#### 3.4.5 第三方工具智能体 (Third-Party Tool Agent)
- **职责**：执行 MCP 工具调用
- **实现**：Eino EnhancedInvokableTool + golang-mcp
- **行为**：
  - 接收主智能体的工具执行请求
  - 调用 MCP 工具（Notion、邮箱、日历等）
  - 返回执行结果
  - 独立工作流处理后台任务（定时闹钟、提醒）

#### 3.4.6 Agent 交互流程
```
用户输入想法
    ↓
Supervisor Agent 接收
    ↓
并行分发：
  - 环境上下文 Agent → 返回相关历史想法摘要
  - 用户画像 Agent → 返回用户画像摘要
    ↓
Supervisor 综合所有信息
    ↓
判断是否需要 MCP 工具调用 → 是 → 工具智能体执行
    ↓
生成结构化响应（JSON + Markdown）
    ↓
返回给用户 + 存入想法簿
```

#### 3.4.7 HITL（人工干预）机制
- 高敏感操作（发送邮件、创建 Notion 页面）需用户确认
- 执行前暂停，展示操作摘要给用户
- 用户确认后继续，24小时未响应则默认拒绝
- 中断状态持久化到数据库，进程重启可恢复

### 3.5 响应数据格式

Agent 返回的结构化数据包含以下字段：

| 字段 | 类型 | 说明 |
|---|---|---|
| `tag` | string[] | AI 自动分类标签（如 #创意 #项目 #学习） |
| `baseInput` | string | 用户原始语音输入（STT 文本） |
| `belongProject` | string | 归属项目名 |
| `aiMeanEnv` | string | AI 对用户真实意图和处境的理解 |
| `feasibility` | object | 想法可行性评估：{level: "高/中/低", reasoning: "分析"} |
| `suggestions` | string[] | 可行的后续行动建议列表 |

返回格式：JSON 信封 + Markdown 摘要（用于 App 展示）

### 3.6 第三方工具集成

#### 3.6.1 预设工具（普通用户友好）
| 工具 | 功能 | 说明 |
|---|---|---|
| Notion | 创建页面、更新页面、查询数据库 | 需用户在设置中配置 Notion API Token |
| 163 邮箱 | 发送邮件 | 需用户在设置中配置 SMTP 凭据 |
| 闹钟/提醒 | 创建提醒、定时通知 | 织脑内置功能，无需外部配置 |

#### 3.6.2 高级配置（高级玩家友好）
- 用户可配置自己的 API Token（LLM API、STT API 等）
- 支持自定义 MCP 端点接入
- 用户显式启用每个自定义工具

### 3.7 账户管理

| 功能 | 说明 |
|---|---|
| 登录/登出 | 正常账号流程 |
| 身份解绑 | 解绑第三方身份提供者，不影响账号数据 |
| 个人信息编辑 | 头像、昵称等 |
| Token 配置 | 高级玩家配置自己的 LLM API Key |
| Token 余额 | 显示当前 Token 使用量和剩余量 |

## 4. 非功能性需求

| 指标 | 目标值 | 说明 |
|---|---|---|
| STT 首字延迟 | < 1s | 从说话到首次流式文字返回 |
| Agent 首响应 | 3-8s | 从输入到 Agent 结构化响应 |
| 可用性 | 99.9% | 后端服务在线率 |
| 并发支持 | 10K | MVP 阶段并发语音会话数 |
| 数据安全 | 加密存储 | 所有 API Key 加密存储 |

## 5. 用户界面概念

### 5.1 首页
- 中央大麦克风按钮（全宽度，最显眼）
- 顶部项目选择器下拉框
- 底部快速入口：想法簿、设置

### 5.2 想法详情
- 卡片式展示
- 显示结构化字段（标签、可行性、建议）
- 支持编辑

### 5.3 想法簿
- 块状时间线视图
- 按项目过滤
- 支持按标签或内容搜索

### 5.4 设置页
- 身份管理（登录/解绑）
- 项目管理（创建/编辑/删除）
- Token 配置
- STT 提供商选择

## 6. 数据模型概述

| 实体 | 关键字段 |
|---|---|
| User | id, display_name, avatar_url, created_at |
| Identity | user_id, provider (wechat/qq/phone), provider_id |
| Project | id, user_id, name, default (bool), created_at |
| Idea | id, project_id, user_id, raw_input, structured_data (JSONB), tags (text[]), created_at |
| UserProfile | user_id, profile_data (JSONB), last_updated_at |
| Reminder | id, user_id, project_id, trigger_time, message, status, created_at |
